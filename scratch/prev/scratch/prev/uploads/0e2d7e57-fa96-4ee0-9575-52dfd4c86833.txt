Ship a polished, production-ready documentation site inside the existing Vite app that:

- Explains Stride quickly: what it is, how to consume it, how to render/export it.
- Shows real, running Remotion `<Player>`examples, not static mockups.
- Lets a visitor steer a character live through a permanently visible playground control region.
- Demonstrates the public API from `src/index.ts`: compositions, cast, presets, schema, factories, and export recipes.
- Keeps the existing studio at `/`working and CI-green.
- Is responsive, accessible, and visually consistent with Stride's art direction.

- Do not implement weather (`rain`,`snow`,`fog`).
- Do not publish to npm or change package privacy/versioning.
- Do not remove v1 compatibility shims.
- Do not change the deterministic render path, `stableId`, gait math, or golden hashes unless a docs bug forces it.
- Do not replace the existing studio or break `scripts/smoke.mjs`.

Use the existing proven stack:

- Vite + React 19 + TypeScript.
- `@remotion/player`, already installed.
- Existing Stride palette, fonts, and SVG rig.
- No new runtime dependencies.

Routing:

- Keep the studio at the root route.
- Add a hash route: `#/docs`and`#/docs/<section>`.
- `src/main.tsx`renders the existing
- `App`for normal routes and lazily loads
- `DocsSite`for
- `#/docs*`.
- Hash routing avoids server rewrite requirements and works in dev, preview, static hosting, and the sandbox preview.

Layering:

- Docs UI lives in `src/docs/`.
- Docs UI is an app consumer, like `src/ui/`.
- Docs UI must not be exported from `src/index.ts`.
- Docs examples should import the public barrel where practical to prove the consumer surface.
