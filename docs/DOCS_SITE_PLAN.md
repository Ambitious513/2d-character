## 1. Goal

Ship a polished, production-ready documentation site inside the existing Vite app that:

- Explains Stride quickly: what it is, how to consume it, how to render/export it.
- Shows real, running Remotion `<Player>` examples, not static mockups.
- Lets a visitor steer a character live through a permanently visible playground control region.
- Demonstrates the public API from `src/index.ts`: compositions, cast, presets, schema, factories, and export recipes.
- Keeps the existing studio at `/` working and CI-green.
- Is responsive, accessible, and visually consistent with Stride's art direction.

## 2. Non-goals

- Do not implement weather (`rain`, `snow`, `fog`).
- Do not publish to npm or change package privacy/versioning.
- Do not remove v1 compatibility shims.
- Do not change the deterministic render path, `stableId`, gait math, or golden hashes unless a docs bug forces it.
- Do not replace the existing studio or break `scripts/smoke.mjs`.

## 3. Technical approach

Use the existing proven stack:

- Vite + React 19 + TypeScript.
- `@remotion/player`, already installed.
- Existing Stride palette, fonts, and SVG rig.
- No new runtime dependencies.

Routing:

- Keep the studio at the root route.
- Add a hash route: `#/docs` and `#/docs/<section>`.
- `src/main.tsx` renders the existing `App` for normal routes and lazily loads `DocsSite` for `#/docs*`.
- Hash routing avoids server rewrite requirements and works in dev, preview, static hosting, and the sandbox preview.

Layering:

- Docs UI lives in `src/docs/`.
- Docs UI is an app consumer, like `src/ui/`.
- Docs UI must not be exported from `src/index.ts`.
- Docs examples should import the public barrel where practical to prove the consumer surface.

## 6. Visual direction

- Subject-specific palette derived from Stride: warm paper, deep ink/forest, saturated orange, electric blue, butter/amber, sage, semantic success/danger.
- Docs should feel like an animation lab field guide: frame rulers, slate chips, palette swatches, layered gradients, subtle grain.
- Fixed topbar with current-section state.
- Anchor jumps land below the fixed nav using `scroll-margin-top`.
- Custom scrollbars matching the palette.
- Staged entrance reveals and hover feedback, but respect `prefers-reduced-motion`.
- No sound; this is a docs/product site, not a game or immersive audio experience.
- Readable contrast on all controls and code blocks.

## 7. Player behavior

- Reusable `DocsPlayer` wrapper:
  - `acknowledgeRemotionLicense`
  - `numberOfSharedAudioTags={0}`
  - custom play/pause, restart, scrubber, frame readout
  - loop where appropriate
  - error fallback
  - deterministic `inputProps`
- Hero and playground may autoplay; secondary examples start paused and can be played.
- Respect reduced motion by disabling autoplay.
- Avoid excessive simultaneous autoplaying Players.
- Do not introduce non-determinism into compositions; UI randomization is allowed only in docs/studio state, not render math.

## 8. Accessibility and responsive behavior

- Label all sliders/selects/switches.
- Keyboard-operable controls and visible focus states.
- `aria-pressed` for segmented toggles.
- Toasts use `role="status"`.
- Mobile: no horizontal overflow; nav remains reachable; playground controls stack below the Player; code blocks scroll internally.
- Test at desktop 1440×960 and mobile 390×844.
